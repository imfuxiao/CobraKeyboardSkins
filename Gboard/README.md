## Gboard

照着 Google 输入法（Gboard）的中文键盘做的一套皮肤，四张设计图放在 `资料/` 下：
`拼音键盘.png`、`数字键盘.png`、`符号键盘.png`、`九宫格数字键.png`，
外加一张按下态的 `拼音键盘 tint.png`。皮肤里以点为单位的数值大多是从这几张图上量出来再折算的，
只有键盘高度例外——设计图是张裁过的截图，按它折算出来的键比真机上的 Gboard 矮一截，见「二 布局」。

Gboard 与 iOS 原生键盘最不一样的三处，也是这套皮肤要还原的三处：

1. **键只有两种颜色**：会上屏的（字母、数字、符号、空格）是白的，改变键盘状态的（Shift、删除、
   ?123、返回、标点）是灰的。除此之外整块键盘上只有一颗彩色键——回车，它是 iOS systemBlue。
2. **扁平**：没有立体下边缘、没有描边，按下就是整块键面换一档色。圆角 8pt——
   唯二的例外是最后一行两端那两颗（左 `?123` / 「返回」、右回车），它们是胶囊。
3. **竖向缝隙是横向的两倍半**：横向 4.4pt、纵向 10.8pt。这个比例一改，整块键盘就不像 Gboard 了。

## 一 配色

**改配色只需要动 `jsonnet/Constants/Palette.libsonnet` 里的九个基色**，其余十几个颜色
（按下态、分割线、候选栏、气泡、深色键面的半透明版本）全部由它们算出来，不会出现
「底色改了、按下态还是旧色」这种对不上的情况。

```jsonnet
local base = {
  background:     pair('#EFEFEF', '#202124'),  // 底板的名义色，本身不画
  letterFill:     pair('#FFFFFF', '#44494C'),  // 白键（深色值按半透明反推）
  functionFill:   pair('#D1D1D1', '#2A2D31'),  // 灰键（同上）
  accent:         pair('#1A73E8', '#8AB4F8'),  // Google Blue，只用在候选栏 / 工具栏 / 长按网格
  primary:        pair('#007AFF', '#0A84FF'),  // iOS systemBlue，回车键
  label:          pair('#1F1F1F', '#E8EAED'),  // 键面主字
  labelMuted:     pair('#6E6E6E', '#9AA0A6'),  // 角标 / 预编辑 / 候选注释
  labelOnAccent:  pair('#FFFFFF', '#202124'),  // 强调色块上的字
  labelOnPrimary: pair('#FFFFFF', '#FFFFFF'),  // 回车键上的字
};
```

每个色都是一对 `{ light, dark }`，上层代码一律只写色名，
到 `main.jsonnet` 最后一步才把整棵配置树 `resolve` 成具体色值，
所以除 `Palette.libsonnet` 外**任何地方都不需要关心当前是深色还是浅色**。

### 七个基色分别落在哪

| 基色 | 浅色 | 深色 | 用在哪 |
| --- | --- | --- | --- |
| background | `#EFEFEF` | `#202124` | 底板的**名义色**，本身不画（见「键盘整体背景」），只用来派生分割线与候选按下态 |
| letterFill | `#FFFFFF` | `#44494C` | 字母 / 数字 / 符号 / 空格 / 九宫格里的数字 / `12·34` / `!?#` |
| functionFill | `#D1D1D1` | `#2A2D31` | Shift、删除、`?123`、`=\<`、返回、逗号、句号、九宫格右列与左侧符号条 |
| accent | `#1A73E8` | `#8AB4F8` | 候选栏首选；工具栏图标按下态；长按网格的选中格 |
| primary | `#007AFF` | `#0A84FF` | 回车键，**整块键盘上唯一的彩色键面**；按下换深一档 |
| label | `#1F1F1F` | `#E8EAED` | 键面主字、候选字 |
| labelMuted | `#6E6E6E` | `#9AA0A6` | 角标（上划符号）、预编辑串、候选注释、工具栏图标、空格上的方案名 |
| labelOnAccent | `#FFFFFF` | `#202124` | Google Blue 块上的字 |
| labelOnPrimary | `#FFFFFF` | `#FFFFFF` | 回车键上的字（systemBlue 两档都够深，一律给白） |

### 派生规则

| 派生色 | 怎么算 | 说明 |
| --- | --- | --- |
| 白键按下 | 浅色向黑压 **20%**（`#CCCCCC`），深色向白提 11% | 见下面「白键按下为什么要压这么狠」 |
| 灰键 / 回车按下 | 向黑压 11% / 14%，深色向白提同样比例 | 起点本来就不是白的，原来的力度够用 |
| 按下字色 | 主字色再重 20% | 按住不放时字也跟着实一档 |
| 深色键面的半透明版 | 白键压到 80%、灰键压到 70% | 见下面「深色键面为什么是半透明的」 |
| 分割线 | 底板色掺一成半主字色 | 符号条里的横线、纵排候选栏的分隔线 |
| 候选序号 | 次要文字色向底板退三成 | 候选条上「候选字 > 注释 > 序号」三档轻重 |
| 键盘整体背景 | 白 / 黑把 alpha 压到 `03` | 见下一节，与 `Skins/default` 一致 |

唯一不从这七个基色派生的是**投影色**（`hintShadow`）：投影是黑的，与配色无关，
浅深两档的差别只在 alpha（`38` / `73`）——底板越暗，投影要越实才看得出来。
换配色时不必动它。

### 键盘整体背景：不画

按键区、预编辑区、工具栏区、纵排候选栏**共用同一份几乎全透明的背景**
（`#FFFFFF03` / `#00000003`，alpha 只有 3/255），底交给系统键盘自己画。
这一条照搬 `Skins/default`，那边四个区域也都指向同一个 `keyboardBackgroundStyle`。

这样做解决了 iOS 26 起的一个老问题：系统从那一版开始在键盘顶部加了一段带圆角的高度，
皮肤的底板色一路铺到顶边，会在那圈圆角处与系统底撞出一条色差。
原先是拿一条自下而上的渐隐带去遮，现在整块不画底，问题不存在了——那套渐变代码也随之删掉。

> **代价：键缝里露出来的是系统键盘底，不是 Gboard 的 `#EFEFEF`。**
> 浅色模式下系统底大约是 `#D1D5DB`，与灰功能键的 `#D1D1D1` 几乎同色，
> `⇧` `⌫` `?123` `⏎` 这些键会糊在底上看不出边界。
> 要保住 Gboard「灰键比底暗一档」的读法，得把 `Palette` 的 `functionFill` 浅色值一起调，
> 这一步没有替你做——它动的是七个基色之一，会改变整套配色的观感。

### 白键按下为什么要压这么狠

参照图 `资料/拼音键盘 tint.png` 里，**Gboard 按下的白键就是底板色 `#EFEFEF`**——
键面直接融进底板，按哪颗全靠气泡告诉你。那套做法的前提是底板由皮肤自己画。

本皮肤不画底板（见「键盘整体背景：不画」），缝里透出来的是系统键盘底，浅色下约 `#D1D5DB`。
按原来的 11% 压出来是 `#E3E3E3`，正好夹在纯白键面和系统底中间，两头都不像，看着跟没按一样。
所以浅色的白键单独压到 **20%（`#CCCCCC`）**——比系统底还暗一点，按下去读作「陷进去」。

`press()` 因此支持浅深两档分开给力度：起点不一样，压同样的比例效果差很远。
深色的键面本来就不白，仍是 11%，再多会刺眼。

### 深色键面为什么是半透明的

深色键盘的底是系统那层模糊，键面透一点会跟着底走，比一块焊死的色好看。
白键压到 80%（`CC`）、灰键压到 70%（`B3`）——两档拉开，**深色下仍分得出白键和灰键**。

基色里的深色值是**按透明度反推**的：叠在系统深色键盘底（约 `#1C1C1E`）上，
`#44494C` @ 80% 合成回来正好是原先的 `#3C4043`，`#2A2D31` @ 70% 合成回来正好是 `#26282B`。
也就是说明度关系一点没变，只是透了一层。改这两个值时记得连 `keyAlpha` 一起算，
否则深色会整体偏亮或偏暗。

按下态用同一档透明度，否则一按下去键面会连带「变实」，看着像闪了一下。
气泡与长按面板取的是**不透明**的基色：它们浮在键上面，再透就跟下面的键糊成一片了。
回车键也不透明——它是整块键盘上唯一的彩色键，透了就压不住。
浅色模式全部不透明：浅色底是亮的，键面再透就糊了。

### 深色模式为什么不是「把浅色反过来」

浅色模式里灰键比底板**暗**、白键比底板**亮**；深色模式里两种键都比底板**亮**，
只是白键更亮一档。这是 Gboard 夜间主题本来的样子：键浮在底板之上，靠亮度分层，
不靠明暗对冲。打样时试过让灰键比底板更暗，结果第三、四行整片糊成一块，看不出键的边界。

## 二 布局

四种键盘**都是四行**，行高完全一致，所以来回切换时键不会跳。
宽度统一按 1125 的虚拟设计宽度分配，一行内所有分子加起来正好 1125 就铺满。

### 高度不按设计图折算

`资料/` 下那几张图是裁过的截图，按图宽折算出来的四行总高只有 205pt，
键的可视高度剩 41pt——装到手机上比 Gboard 矮了整整一截。真机上 Gboard 的键可视高约 48pt，
加上 10.8pt 的纵向缝隙，一行 ≈ 59pt，四行 ≈ 236pt，所以 iPhone 竖屏取 **240**
（横屏 176、iPad 竖 330 / 横 430，见 `Constants/Metrics.libsonnet` 的 `keyboardHeight`）。
胶囊圆角是按「行高减去上下内边距再取一半」算出来的，改高度时它自己跟着走，不必手动对；
但胶囊的**宽度**不会自己跟着走，见下面「最后一行两端的胶囊宽度跟着行高走」。

| 键盘 | 文件 | 版面 |
| --- | --- | --- |
| 拼音 | `Keyboards/Pinyin.libsonnet` | 26 键，第一行带 1~0 角标，第三行最左是上档键 |
| 数字 | `Keyboards/Numeric.libsonnet` | 10 列数字 + 符号，`?123` 切过来的那一页 |
| 符号 | `Keyboards/Symbolic.libsonnet` | 10 列符号，`=\<` 切过来的那一页（类型名 `gboardSymbolic`） |
| 九宫格数字 | `Keyboards/NumberPad.libsonnet` | 左符号条 + 3×3 数字 + 右功能列 + 底部一行 |

每种键盘各出四份（iPhone 竖 / 横、iPad 竖 / 横），**布局完全相同**，
只有键盘高度与按键间距不一样，见 `Constants/Metrics.libsonnet` 的两张表。
iPad 浮动键盘复用 iPhone 竖屏那一份。

### 边缘键的触摸区比显示区大

第二、三、四行两侧的键用 `size` 取触摸宽、`bounds` 取绘制宽：
触摸区一直延伸到屏幕边缘，显示区仍与其余键对齐，边缘键因此更好按。
设计图上「两侧的键比中间宽」就是这么来的。

### 最后一行两端的胶囊宽度跟着行高走

胶囊读不读得出是胶囊，只看**可视宽 ÷ 可视高**：设计图（`资料/拼音键盘.png`）与真机 Gboard
量出来都是 **1.23**（53pt × 43pt），掉到 1.1 以下就开始像个圆。

这两个数是绑在一起的：本皮肤的行比 Gboard 高一档（可视高 49pt，见上一节），
宽度若还照设计图取整格（53pt），比值只有 1.09，这两颗键就被压圆了。
所以 `Keys.widths.rowFourPillLeft/Right` 的可视宽按行高反推成 192/1125（≈61pt），
比值回到 1.25；触摸格再宽出 13 个单位，让触摸区仍抵到屏幕边缘。
九宫格底行的 `bottomWidths.pill`（17/100）是同一笔账。

> **改 `keyboardHeight` 之后要回头核这个比值**，否则最后一行两端会重新变圆。

### 九宫格的结构

上块占 3/4 高、下块一行占 1/4，所以九宫格的行高与其余三种键盘完全一致。
上块是一个 `HStack` 里塞三个 `VStack`（引擎的命名与直觉相反：`HStack` 是行、`VStack` 是列，
但**嵌套是自由的**）：

```
┌──────┬─────────────────┬──────┐
│ 符号 │  1    2    3    │  %   │
│ 列表 │  4    5    6    │  ␣   │   ← 上块 3/4
│      │  7    8    9    │  ⌫   │
├──────┴─────────────────┴──────┤
│ 返回  ,  !?#   0   =  .   ⏎   │   ← 下块 1/4
└───────────────────────────────┘
```

左边那条灰色符号列表是引擎自带的集合视图（`type: numericSymbols`），
内容取自 App 内「数字键盘符号」设置，皮肤能定的只有背景、内边距与分隔线色。

## 三 几处接线上的取舍

设计图是一张静态图，有些键光看图定不下来「点了会怎样」。下面这几处是照着
「Gboard 上这颗键干什么」+「元书只认上下划、不认左右划」两条定的：

| 键 | 点按 | 上划 | 为什么 |
| --- | --- | --- | --- |
| `⇧`（第三行最左） | Shift | **不接上划**（分词符 `'` 在下划，键面不标） | Gboard 中文键盘这个位置放的是分词键，本皮肤反过来：点按给 Shift。它上面就是 `z` 那一行，往上划多半是在够上一行的字母，接了动作只会误触，所以上划留空；角标也跟着去掉——这套皮肤里角标只有一个读法「上划出这个」，上划空了还画角标就是在说假话。分词符仍在下划上。大写态换 `shift.fill`、大写锁定换 `capslock.fill`。**有预编辑文本时整颗键变成 `Esc`（重输）**，这一档优先级最高——正在拼字时按它是要重来，不是要切大小写 |
| `☺` / `,` | 逗号 | 切到表情键盘 | 笑脸画在上排，正好是「上划出什么」的提示，与第一行「角标即上划符号」是同一条读法 |
| 空格 | 空格 | 切中英 | 键面写的是当前方案名（`$rimeSchemaName`，设计图上那个「拼音」）；有预编辑文本时改成「选定」。上划走 `#中英切换`，翻的是 Rime 的 `ascii_mode`。拼音、数字、符号三页共用这一档——中英是跨页面的全局状态，切到哪一页都该能翻，手势记一次就够。九宫格那颗空格在右侧功能列里，另有自己的构造，仍是次选上屏 |
| 回车 | 回车 | 换行 | iOS systemBlue 的胶囊 + ⏎ 图标，按下换深一档的蓝。**不接任何条件样式与通知**，任何状态下都是这一套——原先让它跟着 `returnKeyType` 换「前往 / 搜索 / 发送」文案，实测通知一回到常态前景就求不回来，变成一颗纯蓝的空键；底色反正不随 `returnKeyType` 变，条件与通知就都没必要了 |
| 字母键 | 小写 | 角标上的符号 | 短按弹一个白色圆形气泡，里面是大写字母，右上角重复一次上划符号 |
| `。`（拼音第四行） | 送半角 `.` | — | 键面写作 `。`，中文状态下由输入方案转成全角，与 Gboard 中文键盘一致 |

> **大小写态只换主标签，角标照画。** 状态样式（`uppercasedStateForegroundStyle` /
> `capsLockedStateForegroundStyle`）给引擎的是**整张前景表**，只写一个大写标签的话，
> 一按 Shift 满键盘的角标会跟着消失。`Button.new` 因此把副标签与角标一起拼进这两张表。

### 气泡的层次是两层做出来的

短按气泡浮在按键正上方，两者又是同一个白，不做分界就看不出哪块是气泡、哪块是键面。
**单靠投影做不出来**：引擎给几何图层的投影路径是图层**底边那一道 1pt 的弧**
（`CAShapeLayer.underPath`，本来是给 iOS 那种立体下沿用的），
一条 1pt 的线一模糊，墨量摊开后峰值就没了。

量了 `资料/拼音键盘 tint.png`：气泡正下方最深处比底板暗 13%、摊开约 10pt，
两侧只暗 4%，正上方几乎为零。10pt 宽、13% 深这个量，1pt 的线怎么调都到不了。

所以分两层：

| 层 | 参数 | 管哪一侧 |
| --- | --- | --- |
| 投影 | 半径 4、偏移 `(0, 3)`、alpha 0.45 / 0.65 | 收紧压成底边一道实线，管「下沿」 |
| 描边 | 0.5pt，半透明黑 / 白 `26` | 管左右和上方 |

正好也对上参照图「下方最深、两侧很淡、上方几乎没有」的层次。
Gboard 的气泡本身没有描边，这条线是补引擎的短板。长按符号网格面板用同一套做法。

### 标点为什么要单独摆一次

引擎摆的是文字图层，对齐的是字形的**行盒**（ascent + descent），不是墨迹。
`。` 的小圆缩在全角方框的左下角、`,` 蹲在基线上，行盒摆正了，看着却偏左偏下——
22pt 下句号会偏出去 5.7pt，在一颗 34pt 宽的键上一眼就看得出不在中间。

`Components/Button.libsonnet` 的 `inkOffsets` 存着「墨迹中心相对行盒中心」的偏移（单位 em，
量自 Hiragino Sans GB / Heiti SC / SF Pro），`paint` 按字号折成点值再转成 `insets` 反向挪回来。
凡是走 `paint` 的地方（键面、角标、长按网格里的格子）都自动补，不必逐处去记。

| | 为什么 |
| --- | --- |
| 用 `insets` 不用 `center` | `center` 是比例，键宽随屏幕变，同一个比例到 iPad 上会过头一倍；`insets` 是点值，与屏宽无关 |
| 左右 / 上下取相反数 | `frame.inset` 这样只平移、宽高不变，不会把字挤窄挤扁 |
| 换字体走样了 | 只改 `inkOffsets` 那张表，三套字体实测差异在 0.03em 以内 |

空格两侧那两颗键也是靠它对齐的：笑脸落在 `doubleTopCenter`（0.30）、
逗号与句号共用 `doubleBottomCenter`（0.66）——**同一个数**，所以两边的标点必定在同一条水平线上。
`scripts/gen_demo.py` 也照着这套算，预览图与真机一致。

### 长按弹出的备选符号

长按走的是引擎的 `hintSymbolsGridStyle`（`Components/Button.libsonnet` 的 `longPress` 选项）：
键的上方弹出一条白面板，手指左右滑动改选、抬手上屏，当前那一格底是强调色。
面板与短按气泡同一套白 + 投影，`Constants/Metrics.libsonnet` 的 `hintGrid` 一节定它的尺寸。

字母键一律**三格**：角标（数字 / 符号）+ 小写 + 大写。

**角标一定落在默认高亮的那一格。** 手指一按下去，底下亮着的就是这颗键右上角标着的那个字符，
抬手即出，与上划同结果；要小写或大写再往左右挪一格。剩下两格里，
大写排到离角标**最远**的那一端，小写填中间：

| 角标落在 | 排法 | 哪些键 |
| --- | --- | --- |
| 最左格 | `1 q Q` | `q` `w` `a` |
| 正中格 | `E 3 e` | `e` `r` `t` `y` `u` `i` 与二、三行大部分键 |
| 最右格 | `O o 9` | `o` `p` `l` |

角标居中时两端离得一样远，谁排左边是自由选择，默认把大写放左边；
`Keyboards/Pinyin.libsonnet` 的 `lowerFirstLetters` 列出要反过来的键（目前只有 `v`：`v 、 V`）。

两颗标点键另有自己的六格表：`☺`/`,` 给 `，、；：“”`，`。` 给 `。？！…—·`。

### 长按默认高亮哪一格

**看键位，不看顺序。** 面板比键宽得多，贴着屏幕边的键，面板会被引擎推回屏内
（`TouchView+HintSymbolsGrid` 里那两段 bounds 夹取）；此时若还默认选中间那格，
高亮就落到手指外面去了。所以越靠左的键越往左选：

| 键中心占键盘宽 | 选哪一格 | 拼音第一行落在这一档的键 |
| --- | --- | --- |
| < 0.175 | 最左格 | `q` `w` |
| < 0.275 | 次左格 | `e` |
| 其余 | 正中间那格 | `r` `t` `y` `u` |
| > 0.725 | 次右格 | `i` |
| > 0.825 | 最右格 | `o` `p` |

阈值取在相邻两颗键中心的正中间（第一行十键的中心是 0.05、0.15、0.25……），不会踩到浮点数相等的边界。
第二、三行按各自的行首偏移（0.05 / 0.15）代进同一个式子，`a` 落最左、`l` 落最右，以此类推。
空格两侧那两颗键直接借第一行 `e` 与 `i` 的位置，写成同一个式子，改行首偏移时两边一起动。

字母键只有三格，所以「次左 / 中间 / 次右」三档落到的都是正中那一格——
这三档要到六格的标点键上才分得开。

> **排内容与定高亮共用 `Button.anchorCol`**，所以「角标一定在默认那一格」这条不会因为
> 改了键宽或行首偏移而失效：两边同时跟着动。

数字 / 符号 / 九宫格三页没有配长按备选：那几页的键面本身就是符号表，
Gboard 在这几页上长按给的东西各家版本也不一致，宁可不猜。

### 键盘之间怎么跳

```
拼音 ──?123──> 数字 ──=\<──> 符号 gboardSymbolic
                 │   <──?123──     │
                 └──12·34──> 九宫格 <──12·34──┘
                                │
                                └──!?#──> 引擎自带的分类符号键盘
   三页的「返回」都一步跳回主键盘（拼音）
   自带那块符号键盘有它自己的「返回」，退回九宫格
```

「返回」用的是 `returnPrimaryKeyboard`，不是 `returnLastKeyboard`：后者弹的是键盘类型栈，
连跳几页之后按一次只退一格，要连按好几次才回得到拼音。主键盘是哪一个由用户设置决定。

### 两套符号键盘，为什么本皮肤这套不叫 `symbolic`

引擎在「`keyboardType == symbolic` **且皮肤没有声明 `symbolic`**」时，会挂上自带的分类符号键盘
（`KeyboardUI/.../KeyboardView+Layout.swift` 的 `layoutInternalSymbolic` → `SymbolicView`，
带分类栏、锁定按钮和它自己的「返回」，皮肤配不了也不用配）。
皮肤一旦占用 `symbolic` 这个名字，那块键盘就永远出不来。

所以本皮肤这一页挂在自定义类型 **`gboardSymbolic`** 下：

| 入口 | 去哪 |
| --- | --- |
| 数字页的 `=\<` | 本皮肤的符号页（`gboardSymbolic`） |
| 九宫格的 `!?#` | 引擎自带的分类符号键盘（`symbolic`） |

类型名不在 `Keyboard.KeyboardType` 枚举里时，引擎按 `.custom(named:)` 处理
（`HamsterKit/.../Keyboard+KeyboardType.swift` 的 `from(identifier:)`），所以自定义名字是合法的。
`main.jsonnet` 里 `builders` 那张表的**键就是键盘类型 id**：config.yaml 按它分组、
按键的 `action: { keyboardType: ... }` 写它、产物文件名也由它派生，想再加一页只要往表里添一行。

> **通知节点必须把样式写全。** 引擎在通知生效期间是拿通知节点**当这颗键的样式节点**用的
> （`KeyboardRenderer.updateButtonLayer`）：它按节点里声明过的样式名收集 sublayer，
> 没收集到的当成多余的直接 `removeFromSuperlayer`。
> 所以通知里少写一个 `backgroundStyle`，键的背景层就会被清掉——
> 表现是「一打字，那颗键的底没了」。`backgroundStyle` 与 `foregroundStyle` 两项一个都不能省，
> 哪怕它与常态完全一样。
>
> 条件样式（`styleName` 数组）与通知**混用更要当心**：通知把状态切回常态时，条件前景求不回来，
> 那颗键会只剩背景。回车键原先就栽在这上面，现在它不接条件也不接通知。

### 两处引擎做不到的

- **横排候选之间的细竖线**：`separatorColor` 只对纵排候选栏（`verticalCandidates`）生效，
  横排画不出这条线。纵排是有的。
- **候选栏展开箭头的方向**：Gboard 展开时朝下、收起时朝上，皮肤只能给一个方向。
  这里没取上下箭头，改用朝右的 `chevron.forward`——它读作「还有，往后翻」，
  展开与收起两个状态下都说得通，不像 `⌄` 那样在收起态就指反了。

## 四 这套皮肤需要的引擎改动

引擎原本让 `numberPad` 与 `numeric` 两种键盘类型**共读 `config.yaml` 的 `numeric` 一项**，
于是「10 列数字键盘」和「九宫格数字键盘」没法各自排版。
本仓库在 `KeyboardUI/Sources/KeyboardUI/Reusable/YamsExtensions/Node+.swift` 的
`getKeyboardName` 里加了一段：`numberPad` 先查 `config.yaml` 的 `numberPad` 项，
查不到再回退 `numeric`。只写 `numeric` 的老皮肤行为不变。

## 五 目录结构与构建

```
Gboard/
├── Makefile
├── README.md                  ← 你正在看的这份，也是配色的说明书
├── demo.png                   ← 由 scripts/gen_demo.py 从编译产物生成
├── 资料/                       ← 四张设计图
├── scripts/
│   └── gen_demo.py            ← 从编译产物生成 demo.png
└── jsonnet/
    ├── main.jsonnet           ← 入口：声明要出哪些文件
    ├── Constants/             ← 数据，不含逻辑
    │   ├── Palette.libsonnet    有哪些颜色（换配色只改这个文件）
    │   ├── Colors.libsonnet     这些颜色怎么用（按键角色表）
    │   ├── Fonts.libsonnet      字号
    │   └── Metrics.libsonnet    高度、间距、圆角
    ├── Components/            ← 通用构件，不知道有哪些键盘
    │   ├── Style.libsonnet      样式节点构造 + 深浅色解析（不依赖任何模块）
    │   ├── Theme.libsonnet      角色 → 样式名与样式节点
    │   ├── Button.libsonnet     按键构造，收敛全部命名规则
    │   ├── Keys.libsonnet       白键 / 灰标点键的构造器 + 宽度表
    │   ├── FunctionKeys.libsonnet 功能键，外观 + 动作 + 通知收在一处
    │   ├── Layout.libsonnet     HStack / VStack 语法糖
    │   ├── Preedit.libsonnet    预编辑区
    │   └── Toolbar.libsonnet    工具栏与横 / 纵候选栏
    └── Keyboards/             ← 一种键盘一个文件，只写表
        ├── Pinyin.libsonnet
        ├── Numeric.libsonnet
        ├── Symbolic.libsonnet
        └── NumberPad.libsonnet
```

依赖方向是单向的：`Constants ← Components ← Keyboards ← main`，没有环。
`Style.libsonnet` 不 import 任何东西，与仓库里其他皮肤的同名文件逐字相同。

**没用到的样式不写进产物。** `Style.prune` 在出文件前扫一遍，
把没有任何地方引用的样式节点丢掉，所以加角色不会让每份产物都跟着变胖。

### 常用命令

```bash
make compile    # 只编译出 config.yaml / light/ / dark/
make validate   # 编译后跑结构校验，查「引用了不存在的样式」这类会让按键静默变空白的问题
make preview    # 编译后渲染预览图，查「某行没铺满」这类校验器看不出的几何问题
make build      # 打包成 build/Gboard.cskin，可直接安装
```

在手机上改皮肤时，长按皮肤选择「运行 main.jsonnet」即可重新编译。

### 换一套配色

改 `jsonnet/Constants/Palette.libsonnet` 里 `base` 的七行，重新 `make build` 即可。
`Components/` 与 `Keyboards/` 下的代码一律不必碰，`demo.png` 也会跟着新配色重新生成
（`python3 scripts/gen_demo.py`，它的板底色、标题色、那条强调色细线都是从编译产物里读的）。
